# 查询时序收紧（Timing Tighten）：固定模式 500ms→250ms、轮询读窗口 200ms→250ms

> 状态：规格（已真机验证，2026-08-17，COM9 / 00911008 / A 通道）

## 目标

收紧 `BurnWorker` 中两处过宽的固定等待与轮询读窗口，缩短固定模式的单次查询延迟，同时为 U 命令纳入轮询/读窗口路径留出余量：

1. 固定模式 C 查询后等待：`500ms` → `250ms`（`ExecuteAsync` 内）。
2. `QueryUidAsync`（U 查询）等待：`500ms` → `250ms`。
3. 轮询模式单轮读窗口 `PollingReadWindowMs`：`200ms` → `250ms`（覆盖 U 帧最迟到达时间，为未来 U 轮询留余量）。

## 实测依据（真机，2026-08-17，COM9 / 00911008，9600 波特，20ms 采样粒度）

| 项目 | 完整帧 min/avg/max | p95 |
|---|---|---|
| C 查询（20 轮） | 116 / 129 / 136ms | 133ms |
| U 查询（20 轮） | 163 / 179 / 202ms | 199ms |

**250ms 收紧验证**（50 轮/命令，模拟新时序路径）：

- 固定模式（清缓冲 → 写 → 等 250ms → 一次性读）：C **50/50**、U **50/50** 命中完整帧。
- 轮询窗口（250ms 窗口 + 20ms 粒度读到为止）：C **50/50**、U **50/50** 命中完整帧。

250ms 相对最迟到达（C 136ms / U 202ms）分别留 ~84% / ~24% 余量。

## 范围与非目标

- 只改 `src/BurnMachine/BurnWorker.cs`：两处 `Task.Delay(500, ct)` → `Task.Delay(250, ct)`、`PollingReadWindowMs` 200→250、相关常量注释更新。
- 不改变任何公开 API、协议构造、解析语义、重试/超时/取消逻辑。
- 不动 `ReadResponseAsync` 默认窗口（固定模式 1s/100ms 粒度）——收紧的是"查询后固定等待"，读窗口兜底保持不变。
- 不动其他文件、不加新常量、不引入新依赖。

## 验收标准

- [ ] 固定模式与 `QueryUidAsync` 代码中不再出现 500ms 固定等待。
- [ ] `PollingReadWindowMs` 为 250，注释写明实测依据与余量。
- [x] 全量单测回归通过（119 个用例全部通过，Mock 通道语义不受影响）。

## 数据流与接口变化

无接口变化。时序变化：

```
固定模式：...写 C → await Task.Delay(250ms) → ReadResponseAsync(1s 窗口) → 解析
QueryUidAsync：写 U → await Task.Delay(250ms) → ReadResponseAsync(1s 窗口) → 解析
轮询模式：写 C → ResetInputBuffer → ReadResponseAsync(250ms 窗口, 20ms 粒度) → 解析
```

轮询"窗口 ≤ 剩余时间"的严格超时约束保留（`windowMs = min(PollingReadWindowMs, remainingMs)`），窗口变大不改变总超时上限语义。

## 边界情况与失败处理

| 情况 | 行为（与收紧前一致） |
|---|---|
| 250ms 后响应未到（设备异常慢/噪声丢帧） | 固定模式由 1s 读窗口兜底；轮询模式继续下一轮或判超时 |
| U 命令旧固件无回复 | 250ms 后读空 → NoResponse，与 500ms 时行为一致 |
| 轮询总超时 | 不变（窗口受剩余时间约束） |
| 取消 | 不变（Task.Delay 带 ct） |

## 测试方案

- 时序常量无可测单元逻辑（MockSerialChannel 不模拟真实延迟），主要验证为上述真机数据（已 100% 通过）。
- 改动后跑全量单测（`dotnet test`，119 用例）确认无回归。
- 真机复跑：`burn` 模式端到端 1 次（轮询路径）确认整链路。

## 假设与风险

- 假设设备响应延迟稳定（实测 100/100 命中，C 帧最迟 136ms；若设备变慢超过 250ms 读窗口兜底仍在，仅固定模式"一次命中"概率下降，不影响正确性）。
- 固定模式总响应预算从 ~1.5s（500ms+1s）降至 ~1.25s，可感知延迟下降 ~250ms；无正确性风险。
- 风险低：纯常量/时序调整，无 API 变更。
